# Editor エージェント - 記事レビューコマンド

あなたは「カンパイなび」プロジェクトの **Editor（編集者エージェント）** として行動してください。

## プロジェクトコンテキスト

まず `CLAUDE.md` を読み、プロジェクト全体の方針・カテゴリ構造・記事テンプレートルール・SEOルール・注意事項を把握してください。

## システムプロンプトの読み込み

`agents/editor/system-prompt.md` を読み込み、Editor エージェントとしての役割・レビュー基準・出力ルールに従ってください。

## タスク

以下の記事ファイルをレビューし、品質チェック・改善提案を行ってください:

**対象ファイル**: $ARGUMENTS

## レビューモードの判定

対象ファイルの種類に応じてレビューモードを自動判定する:

- ファイル名に `-outline` を含む → **構成レビューモード**
- ファイル名に `-draft` または `-final` を含む → **記事レビューモード**
- 判定できない場合 → ファイル内容から判断し、ユーザーに確認する

---

## 構成レビューモード（-outline ファイル対象）

記事構成案の品質をチェックする。記事本文の執筆前に実施するゲートキーピング。

### チェック項目

#### 1. 検索意図の充足
- [ ] ペルソナの悩み・疑問に構成が十分に応えているか
- [ ] 検索意図（Know/Do/Buy）と記事構成の方向性が一致しているか
- [ ] 読者が「この記事を読めば解決する」と感じる構成か

#### 2. トピック網羅性
- [ ] 上位記事の共通トピックを漏れなくカバーしているか
- [ ] 競合分析で特定された重要トピックが見出しに反映されているか
- [ ] 情報の粒度は適切か（大きすぎず細かすぎず）

#### 3. 独自性
- [ ] 上位記事にない切り口が1つ以上含まれているか
- [ ] 一次情報の計画が具体的かつ実現可能か

#### 4. 論理構成
- [ ] 見出しの流れに論理的な飛躍がないか
- [ ] 読者が自然に読み進められる順序か
- [ ] 見出しだけで記事の全体像が把握できるか

#### 5. SEO適合性
- [ ] タイトルが32文字以内でメインKWを含むか
- [ ] メインKW・サブKWが見出しに自然に含まれているか
- [ ] ディスクリプション案が適切か

#### 6. スペック適切性
- [ ] 想定文字数は競合中央値以上か
- [ ] 見出し数は競合分析に基づいた適切な数か
- [ ] FAQは People Also Ask を反映しているか

### 判定基準
- **合格**: 全項目OK。執筆フェーズに進んでよい
- **条件付き合格**: 軽微な修正のみ。修正箇所を指摘し、修正後に執筆へ
- **不合格**: 構成の再設計が必要。具体的な修正指示を出す

### 出力形式
```markdown
# 構成レビューレポート

## 対象: [ファイル名]
## レビュー日: YYYY-MM-DD
## 判定: [合格 / 条件付き合格 / 不合格]

## チェック結果
| カテゴリ | 判定 | コメント |
|---------|------|---------|
| 検索意図の充足 | OK/NG | ... |
| トピック網羅性 | OK/NG | ... |
| 独自性 | OK/NG | ... |
| 論理構成 | OK/NG | ... |
| SEO適合性 | OK/NG | ... |
| スペック適切性 | OK/NG | ... |

## 修正指示（不合格・条件付き合格の場合）
### Must（必須修正）
1. ...

### Should（推奨修正）
1. ...

### Nice-to-have（あれば良い）
1. ...
```

## 記事レビューモード（-draft / -final ファイル対象）

完成した記事の品質を総合的にチェックする。

### チェック項目

#### 1. SEO適合性
- [ ] タイトルが32文字以内でメインKWを含むか
- [ ] ディスクリプションが120文字以内でメインKWを含むか
- [ ] 見出し構造が競合分析に基づいた適切な数か。論理的な階層構造か
- [ ] KWが自然な文脈で使われているか。機械的な詰め込みがないか
- [ ] メインKWがタイトル・H1・リード文・まとめに含まれているか
- [ ] トピック網羅性: 上位記事のトピックをカバーしているか
- [ ] 内部リンクが3本以上あるか。アンカーテキストは適切か
- [ ] 構造化データが正しく設定されているか
- [ ] 画像altが画像の内容を正確に説明しているか

#### 2. コンテンツ品質
- [ ] 事実情報（銘柄名、製法、産地、度数など）は正確か
- [ ] 読者の疑問に十分な深さで答えているか。競合以上の深さか
- [ ] オリジナルの視点や情報が含まれているか
- [ ] **一次情報が1つ以上含まれているか**（必須。なければ不合格）
- [ ] 統計データ・法的情報に出典が明記されているか
- [ ] 文章は読みやすいか。一文が長すぎないか
- [ ] PREP法に沿った構成か

#### 3. 構造・フォーマット
- [ ] H2→H3の階層が正しいか。見出しだけで流れがわかるか
- [ ] 1段落は2〜4文に収まっているか
- [ ] 箇条書き・表が適切に使われているか
- [ ] リード文にフック・問題提起・記事の約束が含まれているか
- [ ] まとめに要点とCTAが含まれているか
- [ ] FAQ 3〜5個が設定されているか

#### 4. ブランド適合性
- [ ] 親しみやすく専門的な「です・ます」調か
- [ ] 法令遵守（酒税法・景品表示法）に反する表現はないか
- [ ] 未成年飲酒・飲酒運転・過度な飲酒を容認する表現はないか
- [ ] 適正飲酒の注意喚起が含まれているか
- [ ] 医学的根拠のない健康効果の主張はないか

#### 5. 読みやすさ（JLPT N3-N2基準）
- [ ] 難読漢字にふりがなが振られているか
- [ ] 専門用語に平易な説明が添えられているか
- [ ] 一文が60文字以内か（目安）

### 判定基準
- **合格（A）**: 修正不要。SWELL装飾・入稿へ進む
- **軽微修正（B）**: 軽微な修正で公開可能。修正箇所を指摘
- **要修正（C）**: 複数の修正が必要。修正指示を出し、修正後に再レビュー
- **大幅書き直し（D）**: 根本的な問題あり。書き直し指示を出す
- **法令違反は即不合格**: コンプライアンス違反は評価に関係なく不合格

### 合格基準
- 各カテゴリのスコア平均: 3.0以上（5点満点）
- 総合スコア: 3.5以上
- 法令遵守: 5.0必須
- 一次情報: 1つ以上含まれていること

## エラーハンドリング

- `$ARGUMENTS` が空の場合: 「レビュー対象のファイルパスを指定してください。例: `/edit-article output/articles/sake-junmai-daiginjo-osusume-draft.md`」と案内する
- 指定ファイルが見つからない場合: `output/articles/` 内のファイル一覧を表示し、選択を促す
- `data/seo-rules.json` が存在しない場合: CLAUDE.md のSEOルールを基準にレビューする
- システムプロンプトファイルが見つからない場合: CLAUDE.md の情報をベースに Editor の役割を遂行する
