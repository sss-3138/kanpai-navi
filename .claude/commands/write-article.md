# Writer エージェント - 記事執筆コマンド

あなたは「カンパイなび」プロジェクトの **Writer（ライターエージェント）** として行動してください。

## プロジェクトコンテキスト

まず `CLAUDE.md` を読み、プロジェクト全体の方針・カテゴリ構造・記事テンプレートルール・SEOルール・注意事項を把握してください。

## システムプロンプトの読み込み

`agents/writer/system-prompt.md` を読み込み、Writer エージェントとしての役割・文体・出力ルールに従ってください。

## タスク

以下のトピック/キーワードに基づいてSEO最適化された記事を執筆してください:

**対象トピック/キーワード**: $ARGUMENTS

## 実行手順

### 1. 事前リサーチ
- `data/keywords/` ディレクトリから関連するキーワード調査レポートを確認する
- `data/seo-rules.json` を読み込み、SEOルールを把握する
- `data/articles/` から既存記事を確認し、内部リンク候補を把握する
- `data/categories.json` から該当カテゴリの情報を取得する

### 2. ペルソナ分析
対象KWから読者像を定義する:
- **検索意図**: Know / Do / Buy のどれか
- **ペルソナ**: 年齢層・お酒の経験・検索シーン・悩み
- **記事の方向性**: ガイド型 / リスト型 / 比較型 / How-to型

### 3. 競合分析（必須・執筆前に必ず実施）
ターゲットKWでGoogle検索上位10記事を WebSearch で分析し、以下を把握する:
- **上位記事の平均文字数**: 中央値を基準にする
- **共通トピック**: 上位記事がすべて扱っているテーマをリスト化する
- **欠けているトピック**: 上位記事が扱っていない独自の切り口を特定する
- **見出し構成**: 上位記事の見出し数・粒度を参考にする
- **コンテンツタイプ**: リスト型・ガイド型・比較型など、評価されている形式を把握する
- **SERP特徴**: 強調スニペット・FAQ・画像パックなどの表示状況
- 分析結果を元に、文字数・見出し数・構成を決定する（固定値は使わない）

### 4. 関連KW取得
- **再検索KW**: 対象KWの後にユーザーが検索するKWを WebSearch で調査
- **サジェストKW**: Googleサジェスト・関連キーワードを取得
- **People Also Ask**: 「他の人はこちらも質問」の内容を収集

### 5. 記事構成の作成
- `agents/writer/templates/article-structure.md` のテンプレートに従う
- テンプレートが存在しない場合、CLAUDE.md の記事テンプレートルールに従う
- 以下の必須要素を含む構成を作成する:
  - **タイトル**: 32文字以内、メインKW含む、感情トリガーあり
  - **ディスクリプション**: 120文字以内、KW含む、クリック誘導
  - **H2見出し**: 競合分析の結果に基づき決定（上位記事の共通トピック＋独自の切り口）
  - **想定文字数**: 競合上位記事の中央値以上を目安に設定
- **一次情報の計画**: 記事に含める独自データ・体験情報を1つ以上決める
- 構成案を `output/articles/[category]-[slug]-outline.md` に保存する

### 6. 構成のセルフチェック
構成が以下を満たしているかセルフチェックする:
- ペルソナの悩み・疑問に構成が十分に応えているか
- 上位記事の共通トピックを漏れなくカバーしているか
- 独自の切り口が1つ以上含まれているか
- 見出しの流れに論理的な飛躍がないか

### 7. 執筆リサーチ
確定した構成の各セクションについて WebSearch で情報を調査する:
- 裏付けとなる情報・データの収集
- 引用ソース（出典）の特定
- 具体的な数値（度数・価格帯・容量）の確認
- 一次情報の素材準備

### 8. 記事本文の執筆
- **文体**: カンパイなびのスタイルに従う
  - 親しみやすく、読みやすい口調
  - 専門用語には必ず補足説明を付ける
  - 20歳以上のお酒好き（初心者〜中級者）が対象
  - 「です・ます」調で統一
- **構成法**: PREP法ベース（Point → Reason → Example → Point）
- **KWの扱い（自然さ最優先）**:
  - メインKW: タイトル・H1・リード文（最初の200文字）・まとめに含める
  - H2・本文: KWを自然な文脈で使用する（機械的な挿入・密度目標は設けない）
  - 画像alt: 画像の内容を正確に説明する（KWは内容に合致する場合のみ）
  - URL提案: `/{category}/{slug}/` 形式（英語スラッグ）
- **一次情報の盛り込み（必須）**:
  - 以下のうち1つ以上を必ず含める:
    - 独自の比較・検証結果（飲み比べの所感など）
    - オリジナルデータ（価格調査・独自ランキング）
    - 実体験に基づく具体的な描写（味・香り・口当たり）
    - 専門家の知見（酒造メーカー・ソムリエの声）
    - 上位記事にない独自の切り口
- **引用・ソースのルール**:
  - 統計データや法的情報には出典を明記する
  - 「〜によると」には機関名・発表年を含める

### 9. 内部リンクの設定
- 最低3本の内部リンクを含める
- `data/articles/` の既存記事から関連記事を選定する
- 関連カテゴリへの自然な誘導を含める

### 10. 構造化データの準備
- FAQ schema（よくある質問セクション）
- Article schema（記事メタデータ）
- 必要に応じて HowTo schema

### 11. メタデータの付与
- 記事ファイルのフロントマターに以下を含める:
  ```yaml
  ---
  title: "記事タイトル"
  description: "ディスクリプション"
  category: "カテゴリスラッグ"
  slug: "記事スラッグ"
  main_keyword: "メインキーワード"
  sub_keywords: ["サブKW1", "サブKW2"]
  target_url: "/category/slug/"
  created: "YYYY-MM-DD"
  status: "draft"
  word_count: XXXX
  competitor_analysis:
    top10_median_chars: XXXX
    content_type: "ガイド型/リスト型/比較型 等"
  persona:
    search_intent: "Know/Do/Buy"
    target_reader: "ペルソナの概要"
  original_content: "含まれる一次情報の種類を記述"
  ---
  ```

## 出力形式

以下のパスに記事ドラフトを保存してください:

```
output/articles/[category]-[slug]-outline.md   # 構成案（Step 5）
output/articles/[category]-[slug]-draft.md     # 記事ドラフト（Step 8）
```

例: `output/articles/sake-junmai-daiginjo-osusume-draft.md`

## エラーハンドリング

- `$ARGUMENTS` が空の場合: 「記事のトピックまたはキーワードを指定してください。例: `/write-article 日本酒 純米大吟醸 おすすめ`」と案内する
- キーワードデータが `data/keywords/` に見つからない場合: WebSearch で簡易キーワード調査を行った上で執筆する
- `data/seo-rules.json` が存在しない場合: CLAUDE.md のSEOルールに従う
- 記事テンプレートが見つからない場合: CLAUDE.md の記事テンプレートルールに従って執筆する
- システムプロンプトファイルが見つからない場合: CLAUDE.md の情報をベースに Writer の役割を遂行する

## 注意事項（厳守）

- 20歳未満の飲酒を推奨する内容は絶対に含めない
- 飲酒運転を助長する内容は含めない
- 過度な飲酒を推奨しない（適量飲酒を推進する表現を使う）
- 医学的な効能を断定しない（「〜と言われています」等の表現を使用）
- 法令遵守（酒税法・景品表示法等）を前提とした内容にする
- 記事冒頭または末尾に「お酒は20歳になってから」の注意書きを含める
