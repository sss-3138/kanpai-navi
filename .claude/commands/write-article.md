# Writer エージェント - 記事執筆コマンド（Step 6-7）

構成案（outline）を元に、執筆リサーチと記事本文の執筆を行うコマンドです。
構成レビュー合格済みの `-outline.md` ファイルを入力として使用します。

## プロジェクトコンテキスト

まず `CLAUDE.md` を読み、プロジェクト全体の方針・カテゴリ構造・記事テンプレートルール・SEOルール・注意事項を把握してください。

## システムプロンプトの読み込み

`agents/writer/system-prompt.md` を読み込み、Writer エージェントとしての役割・文体・出力ルールに従ってください。

## タスク

以下の構成案を元に記事を執筆してください:

**対象**: $ARGUMENTS

---

## 事前準備

### 1. 構成案の読み込み
- `$ARGUMENTS` で指定された構成案ファイル（`-outline.md`）を読み込む
- ファイルが見つからない場合は `output/articles/` を検索する
- フロントマターからメインKW、サブKW、ペルソナ情報、競合分析結果を取得する

### 2. リサーチデータの読み込み
- 構成案のフロントマター `research_data` フィールドから、対応するリサーチデータを読み込む
- または `data/keywords/` から関連するキーワードデータを読み込む

### 3. SEOルール・既存記事の確認
- `data/seo-rules.json` を読み込み、SEOルールを把握する
- `data/articles/` から既存記事を確認し、内部リンク候補を把握する
- `data/categories.json` から該当カテゴリの情報を取得する

---

## Step 6: 執筆リサーチ

確定した構成の各セクションについて WebSearch で情報を調査する。

### 実行内容
1. **各H2/H3セクションの裏付け情報を調査**
   - 記述内容の正確性を担保するための情報源を特定する
   - 統計データ・公式情報がある場合は出典を記録する

2. **一次情報の素材準備**
   - 構成案で計画した一次情報（独自比較・オリジナルデータ・実体験描写など）の素材を準備
   - 具体的な数値データ（度数・価格帯・容量）を収集する

3. **引用ソースの特定**
   - 統計データ・法的情報の出典を特定する
   - 「〜によると」で引用する場合の機関名・発表年を確認する

4. **具体的なデータの収集**
   - 銘柄名・蒸留所名・産地・製法などの事実情報を正確に確認する
   - 価格帯・度数・容量などの具体的な数値を収集する

---

## Step 7: 記事本文の執筆

全情報を集約して記事を執筆する。

### 文体ルール
- 親しみやすく、読みやすい口調
- 専門用語には必ず補足説明を付ける
- 20歳以上のお酒好き（初心者〜中級者）が対象
- 「です・ます」調で統一
- PREP法ベース（Point → Reason → Example → Point）

### KWの扱い（自然さ最優先）
- メインKW: タイトル・H1・リード文（最初の200文字）・まとめに含める
- H2・本文: KWを自然な文脈で使用する（機械的な挿入・密度目標は設けない）
- 画像alt: 画像の内容を正確に説明する（KWは内容に合致する場合のみ）
- URL提案: `/{category}/{slug}/` 形式（英語スラッグ）

### 一次情報の盛り込み（必須）
以下のうち1つ以上を必ず含める:
- 独自の比較・検証結果（飲み比べの所感など）
- オリジナルデータ（価格調査・独自ランキング）
- 実体験に基づく具体的な描写（味・香り・口当たり）
- 専門家の知見（酒造メーカー・ソムリエの声）
- 上位記事にない独自の切り口

### 引用・ソースのルール
- 統計データや法的情報には出典を明記する
- 「〜によると」には機関名・発表年を含める

### 必須要素
1. **リード文**（200〜400文字）: フック・問題提起・記事の約束
2. **本文**: 構成案のH2/H3に沿って各セクションを執筆
3. **FAQ**（3〜5問）: 構造化データ対応
4. **まとめ**（200〜300文字）: 要点振り返り・CTA
5. **内部リンク**: 最低3本
6. **適正飲酒の注意喚起**: 記事内に含める

### 構造化データの準備
- FAQ schema（よくある質問セクション）
- Article schema（記事メタデータ）
- 必要に応じて HowTo schema

---

## 出力形式

記事ドラフトを `output/articles/[category]-[slug]-draft.md` に保存する。

### フロントマター

```yaml
---
title: "記事タイトル"
description: "ディスクリプション"
category: "カテゴリスラッグ"
slug: "記事スラッグ"
main_keyword: "メインキーワード"
sub_keywords: ["サブKW1", "サブKW2"]
target_url: "/category/slug/"
created: "YYYY-MM-DD"
status: "draft"
word_count: XXXX
competitor_analysis:
  top10_median_chars: XXXX
  content_type: "ガイド型/リスト型/比較型 等"
persona:
  search_intent: "Know/Do/Buy"
  target_reader: "ペルソナの概要"
original_content: "含まれる一次情報の種類を記述"
outline_file: "output/articles/[category]-[slug]-outline.md"
research_data: "data/keywords/[keyword]-YYYY-MM-DD.json"
---
```

## 次のステップ

記事執筆完了後、以下のコマンドで編集者レビューを受けてください:

```
/edit-article output/articles/[category]-[slug]-draft.md
```

レビュー合格後、SWELL装飾に進みます:

```
/swell-format output/articles/[category]-[slug]-draft.md
```

## エラーハンドリング

- `$ARGUMENTS` が空の場合: `output/articles/` 内の `-outline.md` ファイル一覧を表示し、選択を促す
- 構成案ファイルが見つからない場合: 「先に `/create-outline` で構成を作成してください」と案内する
- キーワードデータが `data/keywords/` に見つからない場合: 構成案のフロントマター情報を元に WebSearch で簡易調査を行う
- `data/seo-rules.json` が存在しない場合: CLAUDE.md のSEOルールに従う
- システムプロンプトファイルが見つからない場合: CLAUDE.md の情報をベースに Writer の役割を遂行する

## 注意事項（厳守）

- 20歳未満の飲酒を推奨する内容は絶対に含めない
- 飲酒運転を助長する内容は含めない
- 過度な飲酒を推奨しない（適量飲酒を推進する表現を使う）
- 医学的な効能を断定しない（「〜と言われています」等の表現を使用）
- 法令遵守（酒税法・景品表示法等）を前提とした内容にする
- 記事冒頭または末尾に「お酒は20歳になってから」の注意書きを含める
