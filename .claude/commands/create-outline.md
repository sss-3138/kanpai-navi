# Create Outline コマンド - 記事構成作成（Step 4）

`/research` で取得したリサーチデータを元に、記事の構成（見出し構成）を作成するコマンドです。

## プロジェクトコンテキスト

まず `CLAUDE.md` を読み、プロジェクト全体の方針・カテゴリ構造・記事テンプレートルール・SEOルール・注意事項を把握してください。

## システムプロンプトの読み込み

`agents/writer/system-prompt.md` を読み込み、Writer エージェントとしての役割・文体・出力ルールに従ってください。

## タスク

以下のトピックについて記事構成を作成してください:

**対象**: $ARGUMENTS

---

## 事前準備

### 1. リサーチデータの読み込み
- `data/keywords/` から対象KWに関連するリサーチデータ（JSONファイル）を読み込む
- リサーチデータが見つからない場合:
  - `data/keywords/` 内のファイル一覧を表示し、該当するものがないか確認
  - それでもない場合、「先に `/research [KW]` を実行してリサーチデータを作成してください」と案内する

### 2. SEOルールの読み込み
- `data/seo-rules.json` を読み込み、SEOルールを把握する
- `data/categories.json` から該当カテゴリの情報を取得する
- `data/articles/` から既存記事を確認し、内部リンク候補を把握する

---

## 構成作成

リサーチデータの全情報を元に記事構成を設計する。

### 実行内容

1. **ペルソナの検索意図を満たす見出し構成を設計**
   - リサーチデータのペルソナ情報（検索意図・悩み・求められる情報）を最優先で反映

2. **SERPs分析の共通トピックを必ずカバー**
   - 上位記事が共通して扱っているテーマは漏れなく見出しに含める
   - ただし丸写しではなく、カンパイなびの視点で再構成する

3. **欠けているトピック・独自の切り口を1つ以上追加**
   - SERPs分析で特定した「上位記事にないトピック」を盛り込む
   - 独自の比較・検証・体験など、一次情報となる要素を計画する

4. **関連KWを見出しに自然に反映**
   - サブKW・再検索KWを見出しに自然な形で含める（機械的な挿入は禁止）

5. **People Also Ask をFAQに反映**
   - リサーチで収集した「他の人はこちらも質問」の内容をFAQセクションに反映

6. **一次情報の計画**
   - 記事に盛り込む一次情報（独自比較・オリジナルデータ・実体験描写など）を具体的に決める
   - 最低1つは必須

---

## 出力形式

構成案を `output/articles/[category]-[slug]-outline.md` に保存する。

```markdown
---
title: "記事タイトル（32文字以内）"
description: "メタディスクリプション（120文字以内）"
category: "カテゴリスラッグ"
slug: "記事スラッグ"
main_keyword: "メインキーワード"
sub_keywords: ["サブKW1", "サブKW2", "サブKW3"]
target_url: "/category/slug/"
created: "YYYY-MM-DD"
status: "outline"
estimated_word_count: XXXX
competitor_analysis:
  top10_median_chars: XXXX
  content_type: "ガイド型/リスト型/比較型 等"
persona:
  search_intent: "Know/Do/Buy"
  target_reader: "ペルソナの概要"
planned_original_content: "含める一次情報の種類を記述"
research_data: "data/keywords/[keyword]-YYYY-MM-DD.json"
---

# [記事タイトル]

## リード文の方針
- フック: [読者の興味を引く一文の方針]
- 問題提起: [読者の悩みに共感する方針]
- 記事の約束: [この記事で得られること]
- 想定文字数: 200〜400文字

## H2: [見出し1]
### 概要
[このセクションで扱う内容の説明]
### 含めるポイント
- ...
### H3見出し（必要な場合）
- H3: [小見出し1]
- H3: [小見出し2]

## H2: [見出し2]
### 概要
...
### 含めるポイント
- ...

[... 以下、必要な数のH2を配置 ...]

## H2: よくある質問（FAQ）
- Q1: [People Also Ask等から設定]
- Q2: ...
- Q3: ...
（3〜5問）

## H2: まとめ
### 概要
- 記事の要点の振り返り
- CTA（次のアクション）の提示
- 想定文字数: 200〜300文字

## 内部リンク候補
1. [リンク先記事] - [挿入予定箇所]
2. ...
3. ...
（最低3本）

## 一次情報の計画
- 種類: [独自比較/オリジナルデータ/実体験/専門家の知見/独自の切り口]
- 具体的な内容: [何をどのように盛り込むか]
- 挿入予定箇所: [どのH2セクションに含めるか]
```

---

## セルフチェック

構成を保存する前に、以下をセルフチェックする:

- [ ] ペルソナの悩み・疑問に構成が十分に応えているか
- [ ] 上位記事の共通トピックを漏れなくカバーしているか
- [ ] 独自の切り口が1つ以上含まれているか
- [ ] 見出しの流れに論理的な飛躍がないか
- [ ] タイトルが32文字以内でメインKWを含んでいるか
- [ ] ディスクリプションが120文字以内で適切か
- [ ] FAQがPeople Also Askの内容を反映しているか
- [ ] 一次情報の計画が具体的か
- [ ] 内部リンク候補が3本以上あるか

---

## 次のステップ

構成完了後、以下のコマンドで編集者レビューを受けられます:

```
/edit-article output/articles/[category]-[slug]-outline.md
```

レビュー合格後、記事執筆に進みます:

```
/write-article output/articles/[category]-[slug]-outline.md
```

## エラーハンドリング

- `$ARGUMENTS` が空の場合: `data/keywords/` 内のリサーチデータ一覧を表示し、選択を促す
- リサーチデータが見つからない場合: 「先に `/research [KW]` を実行してください」と案内する
- `data/seo-rules.json` が存在しない場合: CLAUDE.md のSEOルールに従う
- テンプレートファイルが見つからない場合: CLAUDE.md の記事テンプレートルールに従って構成を作成する

## 注意事項

- 20歳未満の飲酒を推奨する構成にしない
- 過度な飲酒を前提とした記事構成にしない
- 法令遵守（酒税法・景品表示法等）を意識した構成にする
- 適正飲酒の注意喚起セクションを適切に含める
